\subsubsection{Button Components}

Buttons are interactive elements that users click to perform actions. For screen reader users, buttons require descriptive labels that announce their purpose when focused. The implementation uses the \texttt{useScreenReader} hook to provide audio feedback during user interactions.

\begin{lstlisting}[caption={Button component with screen reader announcement}, label={lst:button-sr}]
// File: frontend/src/HomePage/HomePage.jsx

import useScreenReader from '@/modules/common/hooks/useScreenReader';

const { speak } = useScreenReader();

<button
  onClick={handleCreateApp}
  onFocus={() => speak('Create new app button')}
  aria-label="Create new application"
>
  Create App
</button>
\end{lstlisting}

The \texttt{aria-label} attribute provides a text description that screen readers announce automatically. The \texttt{onFocus} event handler uses the \texttt{speak()} function to provide additional audio feedback when users navigate to the button using keyboard controls, ensuring redundant accessibility support.

\subsubsection{Form Validation and Error Messages}

Form validation errors must be announced clearly to screen reader users so they can correct mistakes. The system uses high-priority speech for immediate error notification.

\begin{lstlisting}[caption={Form validation error announcements}, label={lst:validation-sr}]
// File: frontend/src/modules/auth/pages/LoginPage/components/LoginForm/LoginForm.jsx

import useScreenReader from '@/modules/common/hooks/useScreenReader';

const { speak, announceError } = useScreenReader();

const handleSubmit = (formData) => {
  if (!validateEmail(formData.email)) {
    announceError('Invalid email address. Please enter a valid email.');
    return;
  }
  speak('Submitting form, please wait...');
};
\end{lstlisting}

Validation errors use the \texttt{announceError()} function with assertive priority to immediately inform users of problems. Success messages use standard \texttt{speak()} to provide feedback during form submission.

\subsubsection{Core Accessibility Hook}

The \texttt{useScreenReader} hook provides text-to-speech capabilities throughout the application, ensuring consistent screen reader announcements across all components.

\begin{lstlisting}[caption={Core useScreenReader hook implementation}, label={lst:hook-sr}]
// File: frontend/src/modules/common/hooks/useScreenReader.js

const useScreenReader = () => {
  const speak = (text, priority = 'polite') => {
    if ('speechSynthesis' in window) {
      const utterance = new SpeechSynthesisUtterance(text);
      window.speechSynthesis.speak(utterance);
    }
    
    const announcement = document.createElement('div');
    announcement.setAttribute('role', 'status');
    announcement.setAttribute('aria-live', priority);
    announcement.textContent = text;
    document.body.appendChild(announcement);
    
    setTimeout(() => announcement.remove(), 1000);
  };

  return { speak };
};
\end{lstlisting}

This hook combines browser speech synthesis with ARIA live regions. The \texttt{priority} parameter controls announcement urgency: \texttt{'polite'} waits for current announcements to finish, while \texttt{'assertive'} interrupts immediately for critical messages like errors.

\subsubsection{Focus Announcer System}

The focus announcer system provides specialized announcement functions for different interaction contexts, enabling consistent and contextual feedback throughout the application.

\begin{lstlisting}[caption={Focus announcement functions}, label={lst:focus-announcer}]
// File: frontend/src/modules/common/hooks/useScreenReader.js

const announceFocus = useCallback((elementName, elementType) => {
  const message = `Focused on ${elementName} ${elementType}`;
  speak(message);
}, [speak]);

const announceActivation = useCallback((elementName, action) => {
  const message = `${elementName} ${action || 'activated'}`;
  speak(message);
}, [speak]);

return {
  speak,
  announceFocus,
  announceActivation,
  announceError,
  announceSuccess,
};
\end{lstlisting}

The \texttt{announceFocus()} function provides standardized focus announcements across all components. The \texttt{announceActivation()} function announces user actions such as button clicks or menu selections, providing immediate feedback for interactions.

\subsubsection{Component Manipulation Shortcuts}

Component manipulation operations such as resizing, copying, and deleting require audio feedback to inform screen reader users about the results of keyboard shortcut actions.

\begin{lstlisting}[caption={Component resize announcements}, label={lst:resize-sr}]
// File: frontend/src/AppBuilder/AppCanvas/WidgetWrapper.jsx

import useScreenReader from '@/modules/common/hooks/useScreenReader';

const { speak } = useScreenReader();

const handleKeyDown = (e) => {
  if (e.key === '=' && isArrowKey) {
    resizeComponentWithKeyboard(e.key, true);
    const action = 'Expanding';
    const direction = e.key.replace('Arrow', '').toLowerCase();
    speak(`${action} ${componentName} ${direction}`);
  }
};
\end{lstlisting}

When users press the \texttt{=} key followed by arrow keys, the component expands in the specified direction. The screen reader announces the action, component name, and direction, such as "Expanding button component down", providing clear feedback about the resize operation.

\begin{lstlisting}[caption={Component selection announcements}, label={lst:selection-sr}]
// File: frontend/src/AppBuilder/AppCanvas/WidgetWrapper.jsx

const handleKeyDown = (e) => {
  if (e.key === 'Enter') {
    setSelectedComponents([id]);
    speak(`${componentName} ${componentType} selected`);
  }
  if (e.key === 'Escape') {
    setSelectedComponents([]);
    speak('Component deselected');
  }
};
\end{lstlisting}

The Enter key selects components and announces the selection with component type. The Escape key deselects and announces the deselection, enabling keyboard-only component manipulation with audio feedback.

\subsubsection{Code Editor Components}

Code editor components support both single-line and multi-line code input with specialized screen reader support for edit mode navigation and announcement.

\begin{lstlisting}[caption={Single and multi-line code editor navigation mode}, label={lst:codeeditor-sr}]
// File: frontend/src/AppBuilder/CodeEditor/SingleLineCodeEditor.jsx

import useScreenReader from '@/modules/common/hooks/useScreenReader';

const { speak } = useScreenReader();

const handleFocus = () => {
  const label = paramLabel || 'code';
  speak(`${label} code, press Enter to edit, press Escape to exit`);
};

const handleKeyDown = (event) => {
  if (event.key === 'Enter') {
    setIsEditMode(true);
    speak(`Entering ${label}`);
  }
  if (event.key === 'Escape') {
    setIsEditMode(false);
    speak(`Exiting ${label}`);
  }
};
\end{lstlisting}

Code editors implement a navigation mode that prevents accidental edits during keyboard navigation. When focused, the editor announces instructions to press Enter for editing. Upon entering edit mode, the screen reader confirms the mode change. Pressing Escape exits edit mode and announces the transition back to navigation mode.

\subsubsection{Textarea Component}

Textarea components provide multi-line text input with screen reader support for announcing current content and field purpose.

\begin{lstlisting}[caption={Textarea with content announcement}, label={lst:textarea-sr}]
// File: frontend/src/_ui/Textarea/index.js

import useScreenReader from '@/modules/common/hooks/useScreenReader';

const { speak } = useScreenReader();

const handleFocus = () => {
  const label = props['aria-label'] || props.placeholder || 'textarea';
  const currentValue = value || '';
  const announcement = currentValue 
    ? `${label}, current value: ${currentValue}` 
    : label;
  speak(announcement);
};

<textarea onFocus={handleFocus} />
\end{lstlisting}

Textarea components announce their label and current content when focused. For empty fields, only the label is announced. For fields with content, both the label and a preview of the current value are announced, helping users understand the field's purpose and state.

\subsubsection{Implementation Impact and Standards Compliance}

The screen reader implementations described in this document enable blind and visually impaired users to navigate the entire application using only a keyboard, understand the purpose and state of all interactive elements, receive immediate feedback on their actions, and complete all tasks independently without visual cues. These implementations align with Web Content Accessibility Guidelines (WCAG) 2.2 Level AA requirements \cite{WCAG22}, specifically addressing Success Criteria 2.1.1 (Keyboard), 2.4.3 (Focus Order), 2.4.7 (Focus Visible), 4.1.2 (Name, Role, Value), and 4.1.3 (Status Messages). The consistent use of the \texttt{useScreenReader} hook throughout the application ensures standardized announcement patterns and maintainable accessibility features across all components.
